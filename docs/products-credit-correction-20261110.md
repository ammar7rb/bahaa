# تصحيح إدارة المنتجات وطلبات الائتمان

أساس الإصدار: `d80f53407793e2cc519fd5957db2ede6b1681f49`.

- حظر منتجات الائتمان في تعديل المنتج الرقمي والمادي، ودوال السلة المباشرة، وتعديل الكمية، وإعادة الطلب. تستبعد علاقات السلة المنتجات الائتمانية القديمة من الشراء أيضًا.
- صف المنتجات يعرض حساب التاجر بصيغة M المعتمدة، والباقة النشطة، وسعر البيع، وسعر أقدم تقديم محفوظ. السعر القديم المأخوذ من baseline موسوم بأنه غير موثّق تاريخيًا؛ لا يُستبدل بسعر البيع الحالي.
- ترتيب المجموعة يُطبق قبل pagination في الويب وAPI، ويعاد تطبيقه عند استعمال مسارات ترتيب Collections الحالية. المجموعات: الكتالوج، والبحث، وتصنيف محدد. ترتيب قسم الرئيسية يُحفظ في settings.product_order داخل سجل القسم الموجود، مع تحديث product_ids للقسم اليدوي فقط. يبقى القسم التلقائي تلقائيًا ولا تتحول أولوية العرض إلى اختيار منتجات يدوي. الإعلانات المدفوعة وفرز العميل الصريح بالسعر/الاسم محفوظان.
- التخصيص الأول للكود يشترط request_status=1 وstatus=1. لا يتغير الكود الصادر عند الإخفاء أو النقل، ولا يعاد استخدام تسلسل المنتج المحذوف.

فحص الخادم قبل التصحيح: المنتجان المخفيان ذوا الكودين P15-1 وP15-2 لهما أدلة نشر سابقة: الأول 4 أسطر طلبات وقرارا اعتماد، والثاني سطر طلب وقرار اعتماد. لذلك تبقى الأكواد ثابتة. شرط الترحيل المصحح يخص التثبيت الجديد، ولا تُعاد كتابة أكواد الإنتاج.

لا يضيف الإصدار شروط تمويل أو موافقات آلية. يبقى الحد الحالي للرسالة 189 حرفًا ومتطلب طلب مفتوح واحد لكل عميل ومنتج، مع إمكان إرسال طلب جديد بعد الرد.

التحقق: اختبارات فعلية لرفض السلة الرقمية والمادية وإعادة الطلب والسلة القديمة، وقواعد التخصيص وثبات التسلسل، وأولوية SQL قبل pagination للويب وAPI والتصنيف والبحث، وأولوية قسم الرئيسية التلقائي، وحماية أولوية الإعلان المدفوع، وقراءة أقدم سعر محفوظ، وعدم تكرار رد الائتمان وإشعاره.

النشر يستعمل قفل النشر ومطابقة ملفات المصدر وحفظ نسخة الكود وSQL قبل الترحيل. يكتب SHA256 وحجم وموضع SQL في database-backup-verification.json داخل سجل الإصدار الخاص بالخادم. بعد النشر، يتحقق المنفذ من تطابق جميع ملفات المصدر مع commit ومن استجابة الرئيسية وAPI قبل تحديث .deploy-current.
