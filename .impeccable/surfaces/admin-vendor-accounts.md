# Admin vendor accounts

Mode: Operate. Audience: authorized Sigma Care administrators. Job: locate one merchant, inspect identity and financial context, confirm verified funding, record debt, and purchase a package or extra ad with the merchant's actual operating wallet. The same section shows retained transactions.

Direction: inherit the existing Arabic RTL admin shell and customer accounts components. Place the separate «التجار» rail section directly after «العملاء». Keep merchant identity and M account reference visible before each financial confirmation. Use compact search, readable tables, focused dialogs, and contextual navigation when a merchant is selected.

Proof and states: original seller/deposit/ledger/debt/subscription/extra-ad records; pending versus paid versus rejected; debt recovery and net credit; insufficient wallet; active or suspended account. Do not present purchasing quota as money or silently treat a support message as authorization to debit.

Constraints: no parallel financial system; no new migrations; existing light and dark tokens; mobile horizontal table scrolling; keyboard accessible controls; no plaintext secrets in records; no real production financial action for visual verification.
